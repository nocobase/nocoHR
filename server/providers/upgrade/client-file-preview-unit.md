## Retained behavior and scope

- The File UI remains registered at `client/extensions/nocobase-file-component-ui/`. Its real consumers include `CertificateScanButton` on `/talent/certifications` and `/talent/external-certs`, plus the leave-proof path. No page, menu or alternate preview entry was added.
- Certificate scans still use the existing `certificateScanFiles` repository, local storage and protected content route. `externalScan` still checks the holder/viewer before returning metadata; the file route still checks access to the linked certificate. The generated URL is same-origin and is passed through the preview's existing safe-URL resolver.
- The template gap was identified by source comparison; this unit did not demonstrate an exploit against a previously running application. Synthetic `text/html` and XML responses are controlled regression cases, not a claim of a live attack.
- The real business screenshot shows a synthetic PNG scan opened in the certificate page. It does not establish real PDF browser rendering or parsing by the `@silurus/ooxml` engine; the component viewer is mocked in unit tests.
- The only enforced preview budget added here is the target's 180-second asynchronous elapsed-time deadline for OOXML fetch, viewer import and first render. It does not limit memory or file size and cannot isolate synchronous work that blocks the browser event loop. Certificate scan upload limits and storage policy are unchanged.
