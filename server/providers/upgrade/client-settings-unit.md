# Client settings continuity: `.74 → .76`

This unit brings the fixed `.76` list navigation, role list and shared status presentation into the existing NocoHR Settings pages. It adapts them to the application's current URLs and permission grants; it does not replace the Settings route tree or add another settings entry. The `.76` source archive SHA-1 is `a65772d58490af3392b2ce80d120731d115a5f11`.

## Retained application behavior

- `client/pages/settings/routes.ts` keeps the separate Settings navigation surface, page and action grant IDs, and current URLs. The target `.76` `user-detail.tsx` and `user-form.tsx` are not copied: the target collapses the current read-only detail route and its scope-specific `assign-role` cards into an edit flow. That changes both the existing navigation and permission presentation.
- Default access remains the application's split page at `client/pages/settings/default-access/{index,model,panel,api}.tsx`; it is not recreated because `.76` has a composite file layout. Its route and component tests remain in place.
- Sign-in return remains `client/routing/sign-in-return.ts`; it already handles the application redirect contract, base path and unsafe destinations. The target's differently named helper is not added as a second return path.
- The target's `setup-readiness` and `required-role-setup` components are not added as unused setup UI. They have no runtime consumer in the target application composition.
