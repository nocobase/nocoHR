# Native ordinary generation

Configuration proposals and ordinary structured generation now use the official Agents services. Existing business authorization, output validation, review and persistence stay in their owning services. The complete template upgrade remains unaccepted; keep the pull request in draft and do not deploy it.

`native-ai/structured.ts` requires an explicit AuthorizationContext. It rejects `identity.keyScope` before model probing or session creation, then uses the official default and the native background `run/try/get` consumer. It offers no tools, old employee/model selector, text guessing or compatibility retry. Native `OUTPUT_INVALID` maps to the existing `AIShapeError`; missing configuration maps to `AIUnavailableError`; other model failures propagate to each caller's existing error handling. Ordinary calls retain the old runner's default 120-second total generation deadline, with an optional per-call `timeoutMs` and caller `signal`. The deadline starts before native session creation/admission; the remaining budget is passed to the official finite `try({ wait })`. A pending observation or caller cancellation invokes native `abort()` and waits for its execution/persistence/release, then reads the finalized outcome. A cancelled execution rejects with the deadline/caller reason; an already finalized success or original failure is retained. Listeners are removed on every exit, and the official observer releases its timer. The 20-step limit bounds model steps only and does not replace a total deadline for a stalled stream. Learning's separate existing consumer is unchanged. Existing business-specific wording/quote corrections can still request another generation; one native execution does not promise one request for an entire multi-item business task.

Request-driven transitions that dispatch under a stored owner reject scope-bearing credentials first: manual automation start/retry, practical observation/checklist generation, translation requests and profile-summary regeneration. Trusted scheduled work still resolves its stored owner through the existing automation service. Recipient contexts and direct caller contexts are forwarded where they already exist; no permission-intersection policy or new grant is introduced.

Configuration drafting reuses the existing tool name, input schema, draft store and personnel settings page. It may propose only the existing settings/field/approval-chain kinds. There is no apply tool, automatic confirmation, extra HTTP API or new storage. Malformed tool arguments are rejected by SDK input validation before the adapter; current public history omits that invalid tool part. The tests assert absence of a successful tool result and no draft/settings effect, rather than inventing a public error part.

## Verification

- Short deadline and caller-abort regressions use an actual stalled HTTP model stream, SDK and native persistence. Before the fix (`86e3033`), the ordinary deadline, explicit cancellation and task cases all remain unfinished and fail their bounded assertion (3 failed / 44 filtered out); each snapshot case explicitly aborts in cleanup. The real manual dictionary-review task reaches its existing failed terminal state with a finish time, no fallback and no business dictionary mutation. No production scheduler is started.
- Direct deadline coverage uses 500 ms; the task case asserts that production supplied a nearly 120-second remaining budget, then shortens only the real official observation to 300 ms. No model, generator, task handler or persistence service is replaced. Success remains intact after its 300 ms deadline and a later abort, and its listener is removed. An already cancelled caller adds no model/SQL; a native failure concurrent with caller cancellation retains its original failed code. The previous immediate model-failure, invalid-output, configuration, scope/revocation and chat/learning tests stay active.
- The settings tool creates one pending draft and does not call the settings update service. Malformed arguments, a scope-bearing entry and an admitted user whose personnel-administration grant was revoked create no draft or settings effect. - Direct ordinary generation and practical/translation dispatch reject scoped credentials with zero model requests and zero SQL. The existing realtime/background/read/write/restore scope matrix remains active.
- Weekly brief cases moved from the old isolated assistant fixture to actual native generation and persistence. Their business-facts projection remains controlled: only the addressed head receives synthetic facts; length, recipients and empty/invalid/provider-failure/unavailable fallbacks retain the old assertions. Each case uses its own head/team, avoiding notification idempotency conflicts.
- Focused native/business/page selection: **61 passed / 1 failed** across three files. The failure is the unchanged notification-management route assertion already reproduced on both earlier heads. It is active, not skipped.
- Previous migration-unit business evidence (not rerun for the timeout fix): **150 passed** across the nine affected recruiting, profile, performance, talent-review, licensed, HR-settings, wording and practice-prompt files. These exercise actual business routes/repositories; not every generator/schema in those suites runs an external or loopback model.
- Owning server TypeScript, changed-source ESLint, changed-file formatting, document links and diff checks are recorded in the evidence. No dependency, client rendering, build or startup configuration changed; installation/full build/browser acceptance were not repeated. Test applications do boot the production composition against disposable storage.
