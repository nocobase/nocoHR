# Client routing and management integration

The named client surfaces now use the approved Client 3 contracts while retaining NocoHR's separate application, Settings and development shells. The branch still cannot be installed or deployed as a complete application: retained AI/Workflow packages block the dependency graph, and the original application lockfile remains inconsistent with the target manifest.

- Both replacement runtimes stay disabled. Old Client, Server and CLI registrations and all historical migrations remain.
- Device approval is composed behind one closed source gate; it is not an enabled authentication route.
- Full browser acceptance and English running-application screenshots remain unavailable because strict startup fails during the retained AI CLI import.

## Request and storage cost

- Route partitioning is an in-memory traversal on route changes. Authorization continues to use the native snapshot/revision cache. No SQL, lock, transaction, poller, job or schema is added by the shell adapter.
- Native management calls remain authorized by their existing servers. Users uses bounded list/options/detail calls and one native mutation per explicit action. Role editing uses the native role/options reads and a revision-checked mutation.
- The API-key component sample observes two list reads across initial load and post-create refresh, and one explicit create. Closing the reveal clears the raw secret without a request.
- Assignments initially reads options, role and assignments. Labels resolve once per distinct subject type; subject search/page changes request a page of 25. Assign or confirmed revoke makes one native mutation, then refreshes assignments and labels. Permission snapshots may add a cold authorization read.
- Explorer selection reads connections, collection-list pages and the chosen definition; the columns pane adds one physical-schema read. These UI calls are read requests, with native collection discovery bounded by the client's existing pagination limit. Native metadata discovery may perform its own bookkeeping.
- Full-plugin SQL and session-discovery costs are unmeasured. Synthetic component request counts are not presented as production database measurements. There is no new runner-claim, heartbeat or recurring-poll cost.
