## 与总纲冲突的地方

- 离职取消学习任务直接监听员工状态，而不是在岗位变动事件处理器里登记（全局规则 2）。
- 多处业务规则写死：自助可改字段、审批链两级、截止提醒 3 天、计划过期 14 天、考试回写能力的阈值在配置文件而非界面（可定制约定）。
- 表单字段写死，管理员不能追加字段（可定制约定，影响 V1-01、V1-02、V2-05、V3-08 各一条用例）。
- 第十步通知提及收回权限，属第十四步内容（按版本实现）。

## V1-02 补齐（2026-09-29）

按总纲顺序先补 V1-02。服务端 136 项测试（v1-core-hr 17、talent-acceptance、v1-organization、training-acceptance）与前端 26 个文件 226 项测试通过；前后端类型检查、改动文件 ESLint 与 Prettier 通过（`profile-change-dialog.tsx` 中 3 条列表 index key 警告为本轮前已有）。

- 数据：迁移 `202609290008_extend_core_hr_events` 为 jobEvents 增加 source / note / processedAt，为 personnelActions 增加 from 部门岗位、审批依据部门、当前审批人，为 profileChangeRequests 增加 source / attachmentFileId / confidence；种子 112（权限：correctJob、jobEvent.view、hrAssistant.use / extract）、113（演示员工 onboard 事件，孙丽为 source=action）、114（人事助理三项新任务负责人 hr01）。
- 人事设置：审批链追加规则（部门含下级、异动类型、级别名称、三种审批人、插入位置、启用、顺序）、合并开关、审批链预览；每日任务时间（调度改为每 15 分钟检查，按设置时间每天执行一次）；员工自助可改字段；职级顺序；任职信息两个开关。引用的部门、用户、权限集、序列保存时校验。
- 审批链：提交时生成快照；追加级别找不到审批人转 HR 并注明；本人回避向上；相邻同一审批人合并；发起人即审批人的级别（含 HR 级）自动通过，全部自动通过且生效日已到则立即生效。发起页与设置页均有预览。
- 晋升：须同序列且职级更高（按职级顺序，未配置时自然排序），否则 ACTION_PROMOTE_NOT_HIGHER。
- 岗位变动事件：统一写入（异动单 action、更正/补录 manual、导入 import 并按类型判定含 promote），事务提交后交给处理器，处理完写 processedAt，失败由每日任务重试；处理器现有规则：刷新会话、离职取消学习任务（从员工表写入迁出，满足总纲规则 2）。
- 更正任职信息：替代“标记离职”，须填原因，可在人事设置关闭；编辑接口一律拒绝直接改部门/岗位/状态；新建员工写 manual onboard 事件；关闭“导入可修改任职信息”后导入改任职的行报 IMPORT_JOB_CHANGE_DISABLED。
- 人事助理：getMyHrProfile（只读本人）供“我的档案 · 问人事助理”抽屉；转正准备与续签准备（每日，按接收人权限生成摘要，主管版不含合同，只发一次，附预填转正单/续签入口）；附件识别（上传证件/学历/合同扫描件后自动运行，PDF/Word 读文字，生成 source=ai 待审核申请，只含与档案不同的字段；HR 逐字段采纳或改写后通过，结果写入运行记录采纳率）。图片扫描件当前模型无法读取，运行记录为失败并注明原因。
- 界面：异动记录显示来源 Badge 与更正原因；我的档案新增“我的异动记录”；自助修改只显示允许字段；工作台/站内信链接可预填转正单、自动打开续签。
