# NocoHR 用户教程（按岗位和角色）

这份教程按“谁在用”来组织：先讲各角色登录后能做什么、怎么做、应该看到什么，再讲需要几个角色配合才能走完的业务闭环。每一步都对照过当前代码与演示数据；更细的逐条验收点（越权、边界、重复触发等）见 [acceptance-walkthrough.md](acceptance-walkthrough.md)。

演示公司是“启衡精密”（苏州工厂、成都工厂、人力资源部、销售部等），数据来自《01-演示案例》。

## 0. 开始之前

### 0.1 地址和登录

- 地址：`http://localhost:13310/main/`，登录页 `/main/login`，用户名或邮箱都能登录（邮箱是 `xxx@qiheng.test`）。
- 所有演示账号共用一个密码，写在 `storage/hr-demo-accounts.txt` 第 1 行。
- 登录后：电脑上先进“工作台”，手机宽度（< 768px）的员工先进“知识问答”，底部有“学习 · 考试 · 问答 · 自助 · 我的”五个入口。
- 换人：右上角头像 →“退出登录”。两个人要同时操作（审批、互评）时，用一个普通窗口加一个无痕窗口。
- 顶栏右侧依次是：AI 助手、通知（铃铛，带未读数）、组件示例（仅开发环境）、设置（有设置权限的人才有）、主题、头像菜单。

### 0.2 先把演示库恢复到干净状态（建议）

演示库会被验收和录制改动。照教程走之前，先重建一次：

```bash
cd /Users/tangxiaoai/Documents/nocobase3_004/hr
B=storage/backup-$(date +%Y%m%d-%H%M)
mkdir -p "$B"
mv storage/database.sqlite "$B"/
for d in org-sync attendance demo-materials mail; do [ -e storage/$d ] && mv storage/$d "$B"/; done
APP_SERVER_PORT=13310 pnpm dev
```

- 先停掉正在跑的开发服务（运行 `pnpm dev` 的终端按 Ctrl+C，或让启动它的会话停掉）。
- 不要移走 `storage/hr-demo-accounts.txt`，否则密码会重新生成。
- 首次启动会跑完全部迁移和演示种子（几分钟）；当天的每日任务和组织同步在启动后的第一个整刻钟（每 15 分钟检查一次）自动跑一次，在那之前工作台上还没有 AI 员工准备的材料。

### 0.3 飞书：模拟还是真实

- **教程默认用模拟飞书**：`.env.local` 里 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 两行前面加 `#`。如果演示库是在配了真实飞书时重建的（员工绑的是真实飞书账号，模拟渠道找不到人），注释掉这两行、等开发服务重启后，用 hr01 在控制台执行 `await run('talent/org-sync/dev/use-mock')`（`run` 见 0.6）：清掉飞书绑定并按模拟通讯录重新同步。机器人私聊、卡片、通讯录都在本机模拟：
  - 模拟渠道：顶栏“组件示例”→ 模拟渠道 `/dev/im-mock`（用 hr01 打开）。在“发送人”里选成员（王磊 `fs-u-wanglei`、钱进 `fs-u-qianjin`、陈静 `fs-u-mgr-njl`、周宏 `fs-u-mgr-east` 等），可以发消息、看收件箱、点卡片按钮。
  - 模拟通讯录：`storage/org-sync/feishu-mock.json`，改完到“设置 → 组织同步”点“立即同步”。
- **真实飞书**（测试企业“启衡精密”里只有王磊、陈静两个人）：去掉那两行的 `#`，清掉模拟绑定后同步一次，然后在飞书里私聊“NocoHR 助手”。只用来单独测飞书，主线教程不适用。

### 0.4 邮件：本机模拟邮箱

- 业务邮箱默认是模拟模式：来信从 `storage/mail/inbox/<邮箱>/` 读取，收进系统后移到 `processed/`；发出的信写进 `storage/mail/outbox/`，不会真的发出去。
- 重建后收件箱里已经有样例来信，到“邮件往来”`/talent/mail` 点“收信”即可：
  - 对账邮箱（许婷）：蓉川人力本月账单（附件 720 工时，考勤 672）和一封推广邮件。
  - 招聘邮箱（苏晴）：一封只问“请问你们还招人吗”的来信，会进“待归类”。
  - 审核邮箱（林晓）：客户远航汽车要两个机加工车间 CNC 操作工的证书清单和近 12 个月培训记录，并要联系方式（联系方式不会提供）。
- 后续步骤要用的邮件放在 `storage/demo-materials/mail/`，到那一步时复制进收件箱再“收信”：

```bash
# 蓉川人力更正后的账单（两条 192 工时改为 168）
cp storage/demo-materials/mail/billing/*.eml storage/mail/inbox/billing/
# CNC 操作工职位发布后：招聘网站转来的邹鹏简历、周迪要求把周四面试改到下午
cp storage/demo-materials/mail/recruiting/*.eml storage/mail/inbox/recruiting/
```

### 0.5 AI 模型

本机已配置模型。标【需模型】的步骤由 AI 员工完成，结果的措辞每次可能略有不同；没有模型时，大部分 AI 工作会退回规则模板，只是没有说明文字。

### 0.6 手动触发“明天”

很多事情由每日任务触发（异动生效、提醒、转正准备等）。不想等到第二天时：

- 考勤类：人事 › 考勤 → 右上“手动运行定时任务”。
- AI 员工的定时工作：设置 › AI 员工任务 → 对应任务“立即运行”。
- 其他只有接口的任务：用对应账号登录后按 F12，在控制台粘贴下面的函数再调用（例如 `await run('talent/org/maintenance/run', { asOf: '2026-10-08' })`，`asOf` 按北京时间填）。注意：`asOf` 填未来日期时，到那天为止的所有日期规则都会执行且不能撤回，例如在那之前到期的证书会变成“已过期”。只把日期推到这一步需要的那天。

```js
const run = (path, body = {}) =>
  fetch('/main/api/' + path, {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body),
  }).then(async (r) => ({
    status: r.status,
    body: await r.json().catch(() => null),
  }));
```

## 2. 各角色教程

每个任务写成“去哪里 → 做什么 → 应该看到”。

### 2.1 员工（王磊 `emp_njl_1`，手机端可用李敏、钱进、刘洋）

**① 看自己的档案和岗位差距**

- 去哪里：我的档案 `/talent/me`。
- 应该看到：基本信息（手机号只显示自己的）、合同、异动记录、考勤与假期、学习记录、证书墙；“岗位要求与差距”里王磊有 4 项要求，“安全生产与 5S”“岗位安全上岗资格”有差距，必备项排在前面。

**② 请假（页面方式）**

- 去哪里：我的档案 → 考勤与假期 →“申请请假”。
- 做什么：选事假，开始填那天 00:00、结束填次日 00:00（整天），提交。
- 应该看到：整天按那天的班次算，夜班也只算 1 天（例如王磊 10 月 12 日夜班，存成 10-12 22:00 到 10-13 06:00）；不是整天的时间段按填的时间算；提交后状态为审批中，主管收到待审批。

**③ 请假、补卡（飞书私聊方式）【模拟飞书】【需模型】**

- 去哪里：hr01 打开 `/dev/im-mock`，发送人选王磊 `fs-u-wanglei`。
- 做什么：发“我的年假还有几天”；再发“10 月 8 日请一天事假，家里有事”。
- 应该看到：第一句按王磊本人余额回答；第二句得到一张“请假单（人事助理起草）”卡片，带“提交 / 放弃 / 在 NocoHR 中修改”，并提示与哪天的班次冲突。点“提交”后卡片变为已处理，陈静收到审批卡片。

**④ 问制度、问自己的事【需模型】**

- 去哪里：知识问答 `/talent/ask`，或顶栏“AI 助手”。
- 做什么：问“夜班津贴多少”“设备停机多久要做首件检验”“我的合同什么时候到期”“李敏的合同什么时候到期”。
- 应该看到：制度问题有出处（文档编号和版本），由知识助手回答；自己的合同由人事助理回答；别人的信息拒绝回答。

**⑤ 修改个人信息**

- 去哪里：我的档案 →“申请修改信息”，或“问人事助理”说“我搬家了，住址改成……”。
- 应该看到：生成待 HR 审核的修改申请（部门、岗位、证件号不能自助改）；HR 通过后才写进档案，员工收到通知。种子里王磊已有一条待审核申请，所以第一次会先提示“等待审核”。

**⑥ 学习和考试**

- 去哪里：我的学习 `/talent/learning`、我的考试 `/talent/my-exams`、认证项目 `/talent/certifications`。
- 做什么：把指派的课程学完；做《安全实务问答》；打开“CNC 岗位上岗证”看“认证要求 · 你的进度”。
- 应该看到：课程完成后进入学习记录；考试交卷自动判分（简答题等讲师定分）；满足认证要求（课程 + 考试）后自动发证，进度里两项都是对勾。

**⑦ 查工资条**

- 去哪里：我的工资条 `/talent/my-payslips`。
- 应该看到：需要先“验证身份”（输登录密码）才显示金额；通知和飞书推送里从不出现金额。

**⑧ 绩效**

- 去哪里：我的考核 `/talent/my-review`。
- 应该看到：考核周期到“目标设定”阶段后，人事助理起草 2–4 条目标草稿【需模型】；权重合计不是 100 时不能提交。

### 2.2 部门主管（陈静 `mgr_njl`；跨部门范围用周宏 `mgr_east`、何伟 `mgr_cd`）

**① 审批**

- 去哪里：工作台“等你决定”，或 审批 `/talent/approvals`、人事异动 `/talent/actions`。
- 做什么：批准钱进的请假、补卡；审批王磊的调岗单（种子里有一张待审批）。
- 应该看到：请假批准后，与已发布排班冲突的班次立即标为“不能上岗”，并收到最多 3 人的顶班推荐（每人附理由）；调岗单审批页有“影响预览”（直属上级、合同、排班、学习、操作权限等）。

**② 排班和顶班**

- 去哪里：排班 `/talent/schedules`。
- 做什么：选机加工车间和日期范围，套用轮班模板、保存、发布；在有请假冲突的格子里点“顶班推荐”→“发出顶班邀请”。
- 应该看到：保存时逐格校验（请假、休息时间、连续夜班），红色不能保存、黄色要确认；被邀请的同事在飞书收到卡片，第一个接受的进入排班草稿；没有账号或没绑飞书的人会提示原因，不会误报“已发出”。

**③ 看团队**

- 去哪里：员工（只列本部门）、团队看板 `/talent/team-dashboard`、找人 `/talent/find-people`、员工详情 → 画像。
- 应该看到：只看到自己负责范围内的人；画像摘要每句话都能展开对应数据【需模型】；周宏能看到苏州工厂全部（含装配车间），看不到成都。

**④ 能力评定和学习计划**

- 去哪里：员工详情 → 能力 →“评定”；学习计划 `/talent/learning-plans` · 待我确认。
- 应该看到：评定写入能力记录并更新差距；学习教练起草的计划要主管确认后才生效【需模型】。

**⑤ 招聘（用人部门）**

- 去哪里：用工计划 `/talent/workforce-plans`、招聘需求 `/talent/requisitions`、面试 `/talent/interviews`。
- 做什么（何伟）：打开成都 10 月的用工计划，勾“借调”“招聘”后“确定方案”；给生成的招聘需求“提交审批”；在面试里提交评分。
- 应该看到：缺口、加班 / 借调 / 招聘三种方案及可行性；生成招聘需求草稿；看不到候选人的薪资。

**⑥ 绩效**

- 去哪里：团队考核、校准 `/talent/calibration`。
- 应该看到：确认下属目标、填评价；校准页有分布与指引的对比和异常名单。

### 2.3 HR 管理员（林晓 `hr01`）

**① 每天早上：工作台**

- 去哪里：工作台 `/talent/workbench`；顶栏“通知”铃铛。
- 应该看到：
  - 顶部“AI 员工已办完”：由你负责的 AI 员工本周已经办完的事，标明今天几件、本周几件，按 AI 员工和任务分组，每组显示最新一条和“查看”（打开对应单据或页面），默认显示 6 组，可“展开全部”。数字来自 AI 员工的运行记录；只列你负责的任务，比如对账邮箱是许婷的，林晓看不到。没有产出的运行（例如顶班推荐“候选 0 人”）不算办完，不计数也不显示。
  - 下面“等你决定”：今天要处理 / 本周 / 稍后 / 已完成四栏；AI 员工准备的材料（转正准备、续签准备、变动影响清单、用工合规提示）在卡片上直接显示摘要，可以“展开 / 收起全文”；处理完的待办自动关闭；“去处理”直接打开对应单据，例如转正准备打开预选好员工的转正单。

**② 员工档案与导入**

- 去哪里：员工 `/talent/employees`。
- 做什么：新建员工、Excel 导入（“下载模板”→ 填写 → 上传，预览后导入）、“导入能力评定”。
- 应该看到：导入预览逐行指出错误；导入后人事助理做“导入数据体检”（重复、上级成环、缺负责人等）。

**③ 人事异动（入职、转正、调岗、晋升、离职）**

- 去哪里：人事异动 →“发起人事异动”。
- 应该看到：提交前显示审批链预览（发起人恰好是某一级审批人时，该级自动通过）；生效后生成岗位变动记录和“变动影响清单”（组织与权限、直属上级、合同、账号、薪资、排班、能力差距、学习、证书、操作权限等），逐项确认。

**④ 合同与合规**

- 去哪里：合同管理 `/talent/contracts`、用工合规 `/talent/compliance`。
- 应该看到：到期提醒、续签入口；合规提示（如郭凡入职 40 天未签书面合同、陈晨试用期超法定上限、陈静第二次固定期限合同到期），每条引用条款，注明“不是法律意见”。

## 4. 已知限制和注意

- **时间显示**：部分页面按本机（美东）时区显示时间戳，考勤、排班、请假等核心页面按北京时间。
- **飞书**：默认模拟；真实飞书只接通了测试企业里的两个人。
- **邮件**：默认本机模拟邮箱，不会真的发出。
- **AI 结果**：标【需模型】的步骤措辞每次可能不同；看结构和事实是否对，不必逐字一致。
- **当天去重**：演示库启动时已经跑过当天的每日任务，当天再手动触发会显示“已跳过”，用 `asOf` 指定别的日子。
- **会改数据的步骤**：离职、吊销证书、调岗生效等会影响后续步骤；想反复测时先按 0.2 重建。
