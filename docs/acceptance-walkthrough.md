## 1. 准备

### 1.1 地址与登录

- 应用首页是 `http://localhost:13310/main/`。根路径 `http://localhost:13310/` 会显示 Not found。
- 登录页是 `/login`，可以用“用户名或邮箱”登录。
- 登录后首页按权限跳转：电脑宽度先进“工作台”；手机宽度（< 768px）的员工先进“知识问答”。
- 菜单共三组，另有设置页和开发页：
  - 人事：工作台、我的档案、自助、员工、岗位、人事异动、岗位变动、用工合规、合同管理、薪资档案、算薪、社保公积金、我的工资条、排班、考勤、假期、审批、知识问答、知识库、组织架构、人事报表。
  - 招聘：用工计划、招聘需求、职位、候选人、面试、录用、招聘报表。
  - 人才发展：
    - 直接放在组下的页面：待我决定、团队看板、找人、业务数据、修订建议、审计导出、人才盘点、继任计划。
    - 能力体系：岗位体系、能力词典。
    - 学习与培训：我的学习、课程管理、学习任务、学习路径、线下班次、陪练场景、学习计划、讲师、培训评估、译文审核。
    - 考试与认证：我的考试、认证项目、题库、考试管理、培训报表、外部证书核验、实操考核。
    - 绩效：我的考核、团队考核、校准、考核周期、考核方案。
  - 设置（顶栏“设置”，路径 `/settings/...`）：考勤设置、人事设置、持证上岗、学习规则、字段管理、组织管理、组织同步、AI 员工任务、薪酬设置、AI 入口、招聘设置、外部 AI 助手。插件还提供这几项：权限管理（`/settings/authorization`，包括“权限集”和“权限检查器”）、用户（`/settings/users`）、API 密钥（`/settings/api-keys`）、AI（`/settings/ai`，包括 AI 员工和 LLM 服务）。
  - 开发工具（顶栏“组件示例”，路径 `/dev`，只在开发环境出现）：模拟渠道（仅开发环境）、站内信。

### 1.4 时区

- 应用按 Asia/Shanghai 工作（`server/config/talent.ts` 的 `timeZone`）。本机是美东时间，所以应用里的“今天”比本机日历早一天：本文写作时北京时间已经是 2026-09-30。

**办公软件回调（验签）**

- 机器人消息回调：`POST /api/im-callback/feishu`；卡片回调：`POST /api/im-callback/feishu/card`；通讯录变更回调：`POST /api/org-sync-callback/feishu`。
- 签名放在请求头 `x-nocohr-signature`，值是请求体的 HMAC-SHA256 十六进制串，密钥分别是环境变量 `IM_CALLBACK_SECRET` 和 `ORG_SYNC_CALLBACK_SECRET`。当前没有 `.env`，这两个变量都没设置，所以任何回调都会被拒绝。
- “伪造签名被丢弃”可以直接测：

```bash
curl -i -X POST http://localhost:13310/main/api/im-callback/feishu -H 'x-nocohr-signature: bad' -d '{"x":1}'
curl -i -X POST http://localhost:13310/main/api/org-sync-callback/feishu -H 'x-nocohr-signature: bad' -d '{"eventId":"e1"}'
```

期望分别返回 403 `IM_BAD_SIGNATURE` 和 403 `ORG_SYNC_BAD_SIGNATURE`。

- 要测“同一事件重复推送不重复处理”，需要在 `.env.local` 设置 `ORG_SYNC_CALLBACK_SECRET=<自定>`（开发服务器会自动重启），然后：

```bash
BODY='{"eventId":"evt-001"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac '<自定>' | awk '{print $2}')
curl -X POST http://localhost:13310/main/api/org-sync-callback/feishu -H "x-nocohr-signature: $SIG" -d "$BODY"
```

连续发两次，第二次应返回 `duplicate`。

## 3. 与说明书的差异、未实现、需要用户决定

### 3.1 需要用户决定

1. **真实飞书 / 钉钉**：没有同步插件，也没有测试租户。组织同步用 JSON 文件模拟通讯录，机器人和卡片用内存里的模拟传输。生产环境每次发送都会记为 `IM_TRANSPORT_NOT_CONFIGURED`。以下都没做：推送式增量同步、24 小时滚动失败通知、真实凭证配置。
2. **证书 / Offer 模板打印**：证书是可打印的 HTML（`/api/talent/certificates/:id/document`，浏览器另存为 PDF），Offer 函也是 HTML。要用模板打印插件，需要新增渲染依赖。
3. **审计日志插件没有安装**：用 `auditExports` 表（审计导出页的导出记录）、hr-audit 日志、持证上岗的“变更记录”、外部 AI 助手的“调用记录”代替。
4. **`limits.consecutiveMissingReminderDays` 不再使用**：已经被“考勤异常追问”取代。删掉还是改作他用，需要决定。
5. **“设置 → 授权”（权限管理）只有 root 能进**：V1-01、V3-08、V4-13、V4-14 的授权用例要用 nocobase 执行，或者给 hr01 授予授权设置权限。认证的授予历史存在 personnelSettings 行。
6. **邮件渠道没有配置**：候选人邮件（Offer、约面提醒、报到提醒）都记为“尚未配置邮件渠道”，候选人专属链接在界面上看不到。
7. **演示库一次跑完全部种子**：V3-11 的种子预置了销售场景（销售解决方案经理和要求、高原目标 achieved、任职考试 92 分），V3-08、V3-10 的“从零走一遍”与之冲突。另外，启动时已经自动跑过当天的每日任务和全量同步。
