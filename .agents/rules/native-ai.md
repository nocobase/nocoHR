# Native AI in NocoHR

New employee chat, configuration proposals and ordinary structured generation use the official Agents plugin. Model configuration and new conversation storage belong to the plugin. Old configurations and transcripts are retained without automatic conversion.

- Freeze the current template inputs at `.76` / Skills `.44`; use the application lock. Never switch back to the retired AI/Workflow packages. The upgrade completion marker remains `.54` while full source reconciliation and applicable new-environment integration checks remain open.
- `server/providers/native-ai/` registers the existing own-profile read, approved profile-change request and settings-draft tools. Settings drafts never apply configuration; existing personnel administration permission and per-item confirmation remain required. Reject every entry carrying `authorization.identity.keyScope` before refreshing subjects or executing a tool; the current user-only adapter cannot preserve that credential scope. `generateLearningPlan` and `createNativeStructuredAI` reject the same unsupported entry before native session creation. The ordinary structured input requires the original AuthorizationContext; never replace it with a user ID. Request-driven dispatch/retry and manual practical/translation dispatch also reject scoped entry credentials before switching to a stored task owner. Rebuild ordinary users' current authorization for each tool execution. Never treat one successful entry-action check as permission to discard the scope. Keep the original HR services' row/field policy and review boundaries; no caller identity comes from model input. Error details are excluded from the model/public result.
- `training-automation.ts` injects `structuredPlan` separately from other legacy content generation. The production binding in `automation-tasks.ts` uses native background execution, the task owner's current scope, JSON Schema validation and the existing plan service. No legacy retry or parallel fallback execution is used. Existing deterministic rule fallback remains for unavailable/invalid model output; network errors fail the task.
- Mount the identity-keyed `NativeAIProvider` inside the authenticated router region, after plugin authentication and session preparation. Application React providers wrap plugin providers and therefore cannot read authentication there. Availability also follows the existing `talent.aiAssistant/use` check so keyboard shortcuts cannot reveal a hidden HR entry. The official server still owns generic conversation admission and per-user ownership; every HR tool separately rechecks its business grants. Preserve the separate Settings shell and all existing page/action IDs.
- The official Registry `agent-chat` sources live in `client/extensions/nocobase-agent-chat/`. NocoHR additions retain localized HR greetings and `aiTools.<name>` labels. The old `/talent/ask` URL now labels itself HR assistant, without claiming knowledge retrieval.
- The employee drawer and full-page entry use `ChatPanelScope(open: true)` so their official conversation view loads catalogs even when the global header panel is closed. Their embedded header omits the global Close control because the route or drawer owns closing. They share the official controller, history, approval binding and Stop; never add a second transport or automatic resend.
- `markdown-view.tsx` reuses the retained safe URL/image utility. Keep images same-origin or inline raster, unsafe links blocked and CSP unchanged.
- Ordinary framework/HR/content/exam tasks, practice turns and grading, recruiting, profile summaries/people-condition parsing, performance, talent review, transfer notices, recruiting-mail wording and weekly briefs use `native-ai/structured.ts`. It probes the official default, runs one tool-free native background session and maps invalid native output to the existing shape error; existing business validation and rule fallback remain. The employee label no longer selects old employee/model settings. Ordinary generation keeps a default 120-second deadline (`timeoutMs` can override it) and accepts a caller `signal`. Its official finite observation does not cancel by itself: pending/cancelled waits must call native `abort()` and await finalization before business error handling. Preserve the caller reason and any original terminal failure, remove listeners, and never replace this with a detached Promise race. Step limits cannot end a stalled stream.
- AI-entry classification uses the native structured generator with its existing 30-second budget and current caller AuthorizationContext. Only validated keys from the authorized routing table select a row; no text guessing remains in that active path. Vendor-bill reviews use a native background scope with the two existing payroll tools, bound to the admitted bill ID in official configuration. They refresh current business grants, reject scoped credentials before subject refresh, preserve note-only writes and check for existing notes before rule fallback. The retained bill employee setting is an opt-in, not an old model selector. Billing tools do not require human approval and retain a 120-second model deadline.
- Feishu/IM replies now use the native realtime service through `native-ai/im-session.ts`. Preserve current external-user bindings and user/provider/route memory isolation. Only creation supplies trusted business context; restoring or approving must not append a new business user message after the SDK approval response. Restores verify owner and saved channel origin, and never resend history. Recreating the channel service clears its memory map; pending cards restore the original session from their stored binding. Tests recreate this service within the same application/OnlineAgent, not a full execution process.
- The memory entry also retains its verified external addressee. Only a changed binding confirmed in both directions, or a native approval confirmed expired, releases that entry for a new authorized input. Never catch a generic access/configuration/ownership error to create another session. `currentIMApprovals` reads the existing owner-filtered Agents metadata v1 only when public history contains approval candidates; match current execution/message IDs and official `approvalExpiresAt`, rather than treating historical parts as effective waiting. Unknown/incomplete metadata fails closed. The fixed SDK exposes no public expiry projection; this is a read-only adapter to its existing state, with no plugin-state writes or cleanup. Old cards/history stay intact and approval is never resumed by new input.
- `nativeToolApproval` cards store only the four official binding IDs and masked display in existing `imCards.payload`. The IDs come from official assistant message/execution metadata, never model parameters or the callback. Require current external identity, original card addressee and native owner to agree; verify the exact pending tuple and use official atomic `approve` for waiting state and expiry. Unsupported scoped credentials are refused first; each tool checks current permissions and current external binding again. The existing signed `cardId/button` callback, recipient checks, deduplication and old business-card handlers stay in place. Trusted `nativeIMApprovalContext` supplies `feishuCard` audit origin only after a verified card decision; in-app submissions retain their existing source. Accepted decisions are not repeated after model/delivery failure.
- A realtime response has a 120-second model-stream budget with awaited native abort/finalization. Once the stream closes for human approval, its timer is removed; human waiting follows official approval expiry rather than the model deadline. No persistent channel directory, poll, retry or coordinator is added. Production Feishu credentials/channels are not activated by this cutover. See [channel implementation and validation](../../server/providers/upgrade/native-channel-unit.md).
- No production caller binds `createAIRunner` after this cutover. Knowledge uses the staged dual-source integration described below; the IM prompt explicitly directs unsupported tasks to NocoHR. Do not silently remove history/configuration/legacy-tool modules or LangChain dependencies while they still have consumers. Preserve the disabled compatibility/process gates, historical sources and data.

[Chat/learning validation and costs](../../server/providers/upgrade/native-ai-unit.md) and [ordinary generation inventory and evidence](../../server/providers/upgrade/native-background-unit.md) distinguish native persistence, controlled model transport, real HR requests for synthetic employees and actual business draft storage.

Conflict checks intersect the task owner's current knowledge-use and document-view policies before reading full text, refresh before generation and recheck before recording results. Preserve question-source eligibility, restricted-entry rejection and ID-only recipient visibility checks; notification authorization alone does not protect model input. See [conflict authorization evidence](../../server/providers/upgrade/native-conflict-unit.md). The [native Knowledge search unit](../../server/providers/upgrade/native-knowledge-unit.md) registers official native storage, chunk indexing and the official vector queue. HR keyword search remains separate, with use/view policies intersected before body retrieval. Native spaces default to none. Current HR knowledge-use and explicit native read grants are required; related grants also require configured membership, while explicit all-space grants reach declared spaces. Node ACLs cannot widen this hard admission; official direct APIs reject restricted credentials before reducing to a user reader. Aggregate and direct reader searches recheck each hit's current native access and version after retrieval, before returning titles, references or excerpts. Persistent Knowledge Q&A and body/chat search tools remain closed pending official complete-history permission rechecks. No legacy document/index/permission import is performed. The owner confirmed no used old environment/data; only its migration/archive/restore items are not applicable, while historical source preservation and new-environment acceptance remain required.
